# 手机日历先选中再拖动设计

日期：2026-09-29  
状态：待规格确认  
采用方案：手机端先轻点选中任务，再直接拖动或调整时长

## 1. 背景与根因

上一版使用“长按 450ms 后接管拖动”的方式区分页面滚动和任务调整。实际手机测试发现，长按激活后浏览器不一定稳定地把已经开始的纵向触摸序列交给网页拖动逻辑，导致任务很难移动。

本次不再调整长按时间，而是取消手机端长按模型，改为显式的两阶段交互：先选中任务，再操作任务。未选中任务和页面空白始终优先用于浏览；只有已经选中的任务会立即响应移动或缩放。

## 2. 设计目标

- 不再依赖长按时间，消除不同手机浏览器的长按接管差异。
- 用户触碰未选中的任务时不会意外移动或改变时长。
- 选中后拖动立即生效，不再感觉迟钝或难以触发。
- 任务详情仍有明确入口。
- 手机端和电脑端分别采用适合各自输入方式的交互，不改变桌面鼠标习惯。

## 3. 手机端交互规则

### 3.1 首次轻点：选中

- 轻点未选中的任务，只选中该任务，不打开详情。
- 被选中的任务显示明确高亮、抬起阴影和可用的顶部/底部时长抓取点。
- 同一时间只能选中一个任务。
- 轻点另一个任务时，直接切换选中对象。
- 选中动作不修改任务数据。

### 3.2 选中后拖动：移动任务

- 在已选中任务主体上按下并拖动时，立即进入移动状态，不等待长按。
- 拖动继续沿用现有日期列、时间网格、分钟精度、全天区域、待办池投放和边缘自动滚动规则。
- 只有超过现有有效位移阈值后才保存移动；按下后原地松开不修改任务。
- 完成一次移动后任务保持选中，方便继续微调或改变时长。

### 3.3 选中后拖动抓取点：调整时长

- 未选中时，顶部和底部抓取点不接收缩放手势；从这些位置开始滑动仍可正常浏览页面。
- 选中后，顶部抓取点用于调整开始时间，底部抓取点用于调整结束时间。
- 抓取点按下后立即响应，不等待长按。
- 最小时长、分钟精度和一天边界沿用现有规则。

### 3.4 再次轻点：打开详情

- 已选中的任务在没有发生有效拖动的情况下再次轻点，打开任务详情。
- 打开详情时取消任务选中，关闭详情后恢复普通浏览状态，避免用户返回后误拖。
- 键盘 Enter/Space 仍直接打开详情，不要求先选中。

### 3.5 取消选中

以下操作取消当前选中状态：

- 轻点日历空白区域；
- 打开任务详情；
- 切换日、周、月视图；
- 切换时间轴和列表视图；
- 当前任务被删除、退回待办池或不再显示；
- 组件卸载。

页面滚动本身不取消选中，避免用户滚动到新位置后还要重新选中同一任务。

## 4. 页面滚动优先级

- 未选中的任务使用 `touch-action: pan-y`，允许从任务卡片上直接开始纵向滚动。
- 日历空白区域继续正常纵向滚动。
- 只有选中任务主体及其抓取点使用拖动优先的触摸行为。
- 因此用户若想浏览页面，可以从空白处或任意未选中的任务开始滑动；若触碰已选中任务，则表示准备调整它。

## 5. 桌面端行为

- 鼠标按下任务后仍可立即拖动，不要求预先选中。
- 鼠标单击任务仍直接打开详情。
- 鼠标拖动顶部或底部抓取点仍直接调整时长。
- 新增的选中门槛只应用于触摸和触控笔输入。

## 6. 状态与事件设计

### 6.1 状态

- `selectedTaskId`：当前手机端选中的任务，空值表示浏览状态。
- `gesture`：只保存已经开始的有效移动或缩放，不再保存长按等待状态。
- `preview`：拖动中的任务预览，语义保持不变。

### 6.2 事件流程

触摸或触控笔按下未选中任务：

1. 不捕获指针；
2. 不阻止浏览器滚动；
3. 正常轻点完成后通过 click 选中任务；
4. 如果发生页面滑动，浏览器不会产生选择点击，任务不变化。

触摸或触控笔按下已选中任务：

1. 根据按下位置确定 `move`、`start` 或 `end`；
2. 立即捕获指针并进入当前拖动逻辑；
3. 有效移动后展示预览并在松手时保存；
4. 无有效移动时打开详情并取消选中。

鼠标按下任务：直接沿用当前拖动逻辑；无有效移动时打开详情。

### 6.3 移除旧逻辑

- 移除 450ms 长按计时器和长按激活函数。
- 移除 `pending/active/cancelled` 长按阶段。
- 移除长按震动反馈和“已进入移动模式”等提示。
- 移除不再使用的长按常量及对应测试。
- 保留手势取消、指针捕获释放、自动滚动清理和点击抑制机制。

## 7. 视觉与无障碍

- 选中态使用稳定高亮，不使用只在长按瞬间出现的反馈。
- 实际拖动状态在选中态基础上增强阴影或位移，区分“已选中”和“正在拖动”。
- 未选中时弱化或隐藏缩放抓取点，选中后再完整显示。
- 任务可访问名称改为“轻点选中，再次轻点查看；选中后可拖动调整”。
- 选中变化通过 `aria-live` 宣布，例如“已选中任务，可拖动调整时间”。
- 任务元素使用 `aria-pressed` 表示当前选中状态。

## 8. 测试与验收

### 8.1 自动测试

- 触摸未选中任务时不创建拖动手势、不捕获指针。
- 第一次点击未选中任务只设置 `selectedTaskId`。
- 触摸已选中任务时立即创建移动手势。
- 选中任务的顶部/底部抓取点分别进入开始/结束时间调整。
- 已选中任务无位移松手时打开详情并取消选中。
- 点击另一个任务切换选中对象。
- 点击空白、切换视图和任务消失时取消选中。
- 鼠标仍可立即移动、缩放和点击查看。
- 旧长按计时器、震动调用和长按提示不再存在。
- CSS 默认允许纵向滚动，只有选中任务拦截拖动手势。

### 8.2 真机验收

1. 从任意未选中任务上向上或向下滑动，页面顺畅滚动且任务不变化；
2. 轻点任务后出现稳定选中高亮；
3. 再次按住已选中任务拖动，立即移动且无等待；
4. 拖动选中任务的上下抓取点，立即调整时长；
5. 再次轻点选中任务，打开详情且返回后任务不再选中；
6. 点击空白处取消选中；
7. 选中一个任务后点击另一个任务，选中状态正确切换；
8. 电脑端点击和拖动行为无回归。
