# PlanFlow 方案 B：微信登录与用户自有网盘同步设计

日期：2026-09-28
状态：待用户审阅

## 1. 目标与约束

为现有 PlanFlow Web 应用增加多端同步，同时满足以下约束：

- 中国大陆用户可以通过微信公众号完成登录：网页显示公众号二维码和一次性验证码，用户关注公众号并发送验证码后登录。
- 第一版不接入短信注册，避免短信发送产生持续费用。
- 日程数据不存入项目方的中心数据库，而是存入每个用户自己的 OneDrive 或 WebDAV 空间。
- 云端文件在浏览器内加密后再上传；网盘服务商和登录服务只能看到密文。
- 保留离线使用能力；断网时可继续增删改日程，恢复网络后自动合并。
- 项目方使用的后端只处理短时登录状态、微信公众号回调和必要的 WebDAV 转发，不持久保存日程内容。
- 所有可能产生费用的基础设施必须设置免费额度硬上限或失败即停策略，不启用自动付费扩容。

## 2. 第一版范围

### 包含

- 微信公众号验证码登录。
- OneDrive App Folder 同步。
- 通用 WebDAV 同步，并提供坚果云等常见服务的配置说明。
- 本地 IndexedDB 离线数据仓库。
- 端到端加密、自动同步、手动同步、冲突合并和同步状态展示。
- 从当前 `localStorage` 数据的一次性无损迁移。
- 本地导入、导出备份继续可用。

### 不包含

- 手机短信注册或验证码登录。
- 多人共同编辑同一日程、共享日历或权限管理。
- 服务端保存可查询的日程数据库。
- 网页关闭后的系统级后台同步或网盘实时推送。
- 忘记同步口令后的云端解密或找回。
- 针对每一种国内网盘的私有 API 适配。

## 3. 总体架构

系统分为两个相互独立的子系统：

1. **身份子系统**：确认当前用户对应哪个微信公众号 `openid`，只产生一个应用会话身份。
2. **同步子系统**：用户另行授权自己的 OneDrive 或配置 WebDAV，日程密文直接读写到该存储空间。

微信身份不等于网盘授权。用户在新设备上需要再次完成微信登录、网盘授权，并输入同步口令。这一拆分使微信平台无法读取日程，也避免项目方承担所有用户的存储费用。

```text
手机/电脑浏览器
  ├─ 微信登录 ──> Vercel API ──> 微信公众号回调
  │                  └─ 短时登录状态存储（无日程）
  │
  └─ 本地 IndexedDB
       └─ 浏览器端加密/合并
            ├─ OneDrive App Folder
            └─ WebDAV（直连或 Vercel 无状态转发）
```

## 4. 微信公众号验证码登录

### 4.1 前置条件

项目所有者需要有可接收用户消息和配置服务器回调的微信公众号，并准备：

- 公众号 AppID、AppSecret。
- 自定义回调 Token；如启用消息加密，还需 EncodingAESKey。
- 在微信公众平台把生产回调地址配置为 `https://<生产域名>/api/wechat/webhook`。
- 将密钥配置为 Vercel 环境变量，绝不提交到 Git，也不打入前端构建产物。

### 4.2 登录流程

1. 前端调用 `POST /api/auth/wechat/session`。
2. 服务端创建高熵 `sessionId` 和便于手动输入的 6 位验证码，只保存验证码哈希、状态和过期时间；有效期 5 分钟。
3. 页面展示公众号二维码、验证码和倒计时，并每 2 秒轮询会话状态。
4. 用户扫码关注公众号，向公众号发送该验证码。
5. 微信服务器把消息转发到 `POST /api/wechat/webhook`。
6. 回调接口先校验微信签名，再校验验证码是否存在、未过期、未使用；成功后将该登录会话绑定到消息携带的 `openid`。
7. 前端轮询到成功状态后，以一次性兑换票据换取应用会话。服务端设置 `HttpOnly`、`Secure`、`SameSite=Lax` 的签名 Cookie。
8. 验证码立即作废；登录临时记录在到期后自动删除。

服务端使用 HMAC 从 `openid` 派生稳定的应用用户标识。原始 `openid` 不返回前端、不写入普通访问日志，也不进入网盘同步文件。

### 4.3 临时状态存储

第一版采用 `LoginSessionStore` 接口隔离具体实现，生产默认使用 Upstash Redis 免费实例，所有记录必须设置 TTL。只保存：

- 验证码哈希与登录会话 ID。
- `pending / verified / consumed` 状态。
- 经服务端密钥保护的用户标识和过期时间。
- 基础限流计数器。

该存储不保存任务、习惯、分类、用户名或网盘凭据。项目账户关闭自动付费升级；额度耗尽时登录暂时失败并显示明确错误，不产生账单。

### 4.4 防滥用

- 对 IP、会话和验证码创建接口限流。
- 验证码一次性使用，连续猜测超过阈值即作废。
- 严格校验微信签名、时间戳和重放窗口。
- 回调仅接受文本验证码需要的字段，XML 解析禁止外部实体。
- Cookie 签名密钥定期轮换；登出立即清除本地会话 Cookie。

## 5. 用户自有网盘

### 5.1 OneDrive

- 使用 OAuth 2.0 Authorization Code + PKCE。
- 仅申请应用文件夹权限 `Files.ReadWrite.AppFolder`，数据放在 OneDrive 的应用专属目录。
- OAuth token 不进入项目方数据库；刷新凭据在本机保存，并使用同步口令派生的密钥加密。
- 每台新设备分别完成一次 OneDrive 授权。

### 5.2 WebDAV

- 用户填写 WebDAV 地址、用户名和应用专用密码。
- 若服务支持浏览器 CORS，优先由浏览器直连。
- 若不支持 CORS，请求经 `/api/storage/webdav/*` 无状态转发；转发接口不记录 Authorization、URL 查询参数或响应正文，不缓存凭据。
- WebDAV 凭据以同步口令派生的密钥加密后保存在本机；页面重新加载后默认要求用户再次输入同步口令解锁。
- 只允许 HTTPS，并对转发目标做协议、端口、DNS 和内网地址校验，防止 SSRF。

WebDAV 转发会消耗 Vercel 流量，因此设置单文件大小、请求频率和总流量保护。超过免费额度时暂停自动同步，并允许用户导出本地备份，不自动付费。

## 6. 本地数据模型与迁移

IndexedDB 成为运行时数据源，包含以下逻辑集合：

- `categories`
- `tasks`
- `habits`
- `profile`
- `syncMetadata`
- `tombstones`

每条可同步记录至少包含：

```ts
type SyncRecord<T> = {
  id: string;
  value: T | null;
  updatedAt: string;
  logicalClock: number;
  deviceId: string;
  deletedAt?: string;
};
```

首次运行新版时：

1. 检测现有 `planflow_categories`、`planflow_tasks`、`planflow_habits` 和 `planflow_username`。
2. 在一个迁移事务中写入 IndexedDB，并记录迁移版本。
3. 校验记录数量和关键字段后才标记迁移成功。
4. 暂时保留原 `localStorage` 数据作为回退副本；用户完成一次导出备份后再提供清理入口。

迁移失败不会修改旧数据，应用回退为只读提示并提供导出。

## 7. 云端文件与加密

每个用户的网盘只维护一个主文件 `planflow-sync-v1.bin`，另可保留有限数量的恢复快照。

明文载荷包含：

- 数据格式版本。
- 所有活动记录和删除墓碑。
- 已知设备与逻辑时钟。
- 最近成功同步元数据。

加密封装使用 Web Crypto API：

- AES-256-GCM 加密载荷并校验完整性。
- 密钥由用户同步口令通过 PBKDF2-SHA-256 和随机 salt 派生；算法、迭代参数和版本写入封装头，便于未来升级。
- 每次写入生成新的随机 IV。
- 云端文件只暴露格式版本、KDF 参数、salt、IV 和密文，不包含可读日程。
- 同步口令和派生密钥不上传到项目方服务；派生密钥仅在当前页面会话内存中存在。

如果用户忘记同步口令，云端密文无法恢复。界面必须在首次设置时明确提示用户保存口令，并提供加密文件和本地明文备份的导出能力。

## 8. 同步与冲突合并

### 8.1 触发时机

- 登录并解锁存储后。
- 应用启动和重新回到前台时。
- 本地变更停止 2 秒后。
- 用户点击“立即同步”时。
- 断网恢复后。

### 8.2 上传保护

读取云端文件时保存 ETag；写入使用 `If-Match` 条件请求。若返回冲突状态，客户端必须重新下载、解密、合并后再重试，绝不直接覆盖未知的新版本。

### 8.3 合并规则

- 合并粒度为单条任务、习惯、分类或资料记录。
- 每个设备维护单调递增逻辑时钟；读取远端后，本地时钟提升到已见最大值。
- 同一记录发生冲突时，较大的 `logicalClock` 胜出；时钟相同时用 `deviceId` 做确定性排序，确保所有设备得到同一结果。
- 删除以墓碑表示；墓碑胜过更早的活动版本，防止其他设备把已删除项目复活。
- 墓碑至少保留 90 天；清理前必须确认所有已知活跃设备都已观察到该版本。长期离线设备重新上线时执行完整合并。
- 若任务和分类同时修改，记录各自独立合并；引用已删除分类的任务自动归入“未分类”，不删除任务。

离线情况下无法准确判断两台设备操作的真实先后，因此同时编辑同一条记录采用确定性的最后写入胜出规则；第一版不提供字段级协同编辑。

## 9. 初次连接与恢复策略

- 本地有数据、云端为空：展示将上传的项目数量，用户确认后创建云端文件。
- 本地为空、云端有数据：验证口令后下载并导入。
- 两端都有数据：先在内存中合并，展示新增、更新、删除数量；用户确认后同时更新本地和云端。
- 口令错误、密文损坏或格式版本不支持：禁止上传覆盖；保留本地数据和原云端文件，并提示导出诊断包。
- 切换网盘账号：视为新存储目标，必须重新确认是上传本地、下载远端还是合并。

## 10. 用户界面

设置页新增“账户与同步”：

- 微信登录状态、登录/退出按钮。
- 存储提供方选择：OneDrive 或 WebDAV。
- 同步口令设置与解锁。
- 最近同步时间和状态：已同步、等待网络、同步中、需要重新授权、冲突已合并、同步失败。
- “立即同步”“断开存储”“导出本地备份”“导入备份”操作。
- 初次合并摘要和不可恢复风险提示。

主界面仅显示轻量状态图标，不阻塞用户离线编辑。错误提示包含可执行的恢复动作，不只显示错误码。

## 11. 代码边界

计划采用以下模块边界，具体文件名可在实施计划中按现有项目结构微调：

- `data/localRepository`：IndexedDB、迁移和事务。
- `sync/crypto`：加密封装、KDF 和版本升级。
- `sync/merge`：记录级合并、墓碑和逻辑时钟。
- `sync/engine`：同步状态机、重试、前后台触发。
- `storage/provider`：统一的读取、条件写入、授权刷新接口。
- `storage/onedriveProvider` 与 `storage/webdavProvider`：具体适配器。
- `auth/wechatClient`：前端登录会话。
- `api/auth/*`、`api/wechat/webhook`：Vercel 服务端函数。
- `api/storage/webdav/*`：受限无状态转发。

组件只依赖数据仓库和同步状态，不直接访问 `localStorage`、OneDrive 或 WebDAV。

## 12. 错误处理与可观测性

- 网络错误进入指数退避队列，不丢弃本地操作。
- 401/403 暂停同步并请求重新授权。
- 412 触发重新下载和合并。
- 429 尊重 `Retry-After`，停止高频轮询。
- 网盘空间不足时停止上传并保留本地数据。
- 解密或完整性校验失败时绝不覆盖远端。
- 日志只记录匿名错误类别、请求耗时和同步阶段，不记录日程正文、口令、token、WebDAV 凭据、原始 `openid` 或完整存储 URL。

## 13. 测试策略

- 单元测试：加密往返、错误口令、密文篡改、逻辑时钟、删除墓碑和所有冲突组合。
- 迁移测试：当前四类 `localStorage` 数据、空数据、损坏数据和重复执行。
- Provider 合约测试：读取、首次创建、ETag 条件写入、401、403、412、429、配额不足。
- 服务端测试：微信签名、过期验证码、重复使用、暴力猜测、Cookie 属性、XML 攻击和 SSRF 防护。
- 端到端测试：两种浏览器创建、拖动、缩放、删除同一日程；离线修改后恢复；新设备恢复；同时修改冲突。
- 安全检查：构建产物无 AppSecret，日志无敏感字段，云端样本无法看到明文日程。

## 14. 分阶段实施

1. 建立 IndexedDB 数据仓库、现有数据迁移和备份回退，保持当前 UI 行为不变。
2. 实现加密封装、合并算法和可替换的存储 Provider 接口。
3. 接入 OneDrive App Folder，完成两设备同步闭环。
4. 接入 WebDAV 直连与受限转发，补齐流量保护。
5. 接入微信公众号验证码登录和临时状态存储。
6. 完成设置页、同步状态、错误恢复和全链路测试。
7. 在预览环境进行双设备验收，再发布到现有 Vercel 生产域名。

每一阶段都必须保持本地模式可用；任何云服务故障不能阻止用户查看和编辑已缓存的数据。

## 15. 验收标准

- 同一用户在手机和电脑上通过公众号验证码登录，并连接同一个自有网盘后，可同步任务、分类、习惯和资料设置。
- 在任一设备创建、拖动、延长、缩短或删除计划，另一设备同步后结果一致。
- 两台设备离线修改不同记录后均不丢失；修改同一记录时按确定性规则收敛。
- 网络中断、token 过期、ETag 冲突和网盘配额不足均不会静默覆盖或删除本地数据。
- 网盘中的日程文件为密文；临时登录存储、Vercel 日志和项目方服务中不存在日程正文。
- 第一版不调用短信服务，不建立中心日程数据库，不开启任何自动付费扩容。
- 原有本地数据完成迁移，原有手机端周视图、拖动和缩放功能不回退。

## 16. 已知限制与费用边界

“项目方不承担费用”通过架构和配额控制尽量实现，但免费云服务不能保证永久不改变政策。系统采取以下边界：

- 用户自己的 OneDrive/WebDAV 承担文件存储配额。
- 项目方只承担极小的登录临时状态和可选 WebDAV 转发流量。
- 所有项目方基础设施关闭自动付费升级并设置用量告警；免费额度耗尽时功能降级或暂停，不产生自动账单。
- WebDAV 大流量用户优先引导使用浏览器直连或 OneDrive，避免转发成为公共带宽服务。
- 微信公众号本身的资质、认证规则和可能费用由公众号平台决定，需要在上线前按账户当前状态核验。
