# 手机日历长按拖动手势设计

日期：2026-09-29  
状态：待规格确认  
采用方案：方案 A——长按激活移动或调整时长

## 1. 背景与问题

手机端日程页同时存在三种纵向手势：

1. 上下滑动日历页面；
2. 上下移动某个任务；
3. 拖动任务顶部或底部以改变时长。

当前实现从任务卡片收到 `pointerdown` 开始，就阻止默认行为、捕获指针并进入拖动判定。任务卡片和缩放抓取点还使用了 `touch-action: none`。因此用户只是从任务卡片上开始滑动页面，也可能误移动任务或修改时长。

本次调整遵循 Apple 日历“按住日程后再拖动或调整抓取点”的模式，并采用 Android 推荐的移动阈值来区分轻微抖动、页面滚动和主动拖动。

## 2. 设计目标

- 用户从任务卡片上开始上下滑动时，页面应正常滚动，任务数据不变化。
- 移动任务和调整时长都必须先长按激活。
- 长按激活必须具有明确的视觉和触觉反馈。
- 轻点查看任务详情的行为保持不变。
- 桌面端鼠标拖动行为保持不变，不增加长按等待。
- 不改变当前分钟精度、跨日期移动、自动滚动和保存逻辑的业务含义。

## 3. 移动端交互规则

### 3.1 普通浏览

- 手指按下任务卡片时先进入 `pending` 状态，不立即阻止浏览器默认滚动。
- 在长按时间到达前，如果手指移动超过 10px，则取消长按候选，本次手势完全交给日历滚动容器。
- 被取消的候选不得更新预览、捕获指针、启动边缘自动滚动或写入任务数据。
- 未发生明显移动且快速抬手，按普通点击处理，打开任务详情。

### 3.2 移动任务

- 在任务主体上持续按住 450ms 后，激活 `move` 状态。
- 激活后才捕获当前指针、禁止该次手势继续滚动并启动拖动预览。
- 用户继续拖动时，沿用现有日期列、时间网格、分钟精度和放置目标计算。
- 松手时只提交最终位置一次；未产生有效位移则不修改任务。

### 3.3 调整任务时长

- 顶部和底部抓取点在未激活时不能立即调整时长。
- 在顶部抓取点长按 450ms 后进入 `resize-start`；在底部抓取点长按 450ms 后进入 `resize-end`。
- 长按时间到达前移动超过 10px，仍视为页面滚动，不调整时长。
- 激活后沿用当前最小时长、分钟精度和时间边界规则。
- 抓取点的视觉触控区域可以大于可见线条，但不得因此阻止普通页面滚动。

### 3.4 激活反馈

- 长按成功时卡片进入抬起状态：提高层级、增强阴影和边框。
- 对支持振动 API 的设备触发一次约 15ms 的轻震；不支持时静默跳过。
- 移动状态和调整时长状态使用不同的光标/抓取点高亮，避免用户不知道当前动作。
- 屏幕阅读器获得简短状态提示，例如“已进入移动模式”或“已进入调整结束时间模式”。

### 3.5 取消与清理

以下情况必须取消候选或活动手势，并清除计时器、指针捕获、自动滚动和预览：

- `pointercancel`；
- `lostpointercapture`；
- 页面或组件卸载；
- 多指触控介入；
- 长按前位移超过阈值；
- 当前任务在手势期间被删除或变为不可编辑。

取消不得保存部分移动结果。

## 4. 桌面端行为

- 鼠标主键按下后仍可立即移动任务或拖动抓取点，不等待 450ms。
- 键盘打开详情和现有点击行为不变。
- 长按门槛仅适用于触控型指针；触控笔按触控逻辑处理，以减少误操作。

## 5. 技术设计

### 5.1 手势状态机

移动端手势分为：

- `idle`：无活动手势；
- `pending`：等待长按，允许页面滚动；
- `active-move`：任务移动已激活；
- `active-resize-start`：开始时间调整已激活；
- `active-resize-end`：结束时间调整已激活；
- `cancelled`：本轮交给滚动或已被系统取消，直到指针抬起。

状态只能从 `pending` 在计时完成后进入一种 `active-*` 状态。任何超过阈值的提前移动都从 `pending` 进入 `cancelled`，不能在同一次触摸中重新激活。

### 5.2 常量

- `LONG_PRESS_MS = 450`
- `TOUCH_SLOP_PX = 10`
- `HAPTIC_MS = 15`

常量集中定义并通过纯函数测试，避免散落在组件事件代码中。

### 5.3 事件边界

- `pointerdown`：记录起点并启动长按计时器；触控端不立即 `preventDefault` 或 `setPointerCapture`。
- `pointermove`：在 `pending` 状态只检查位移阈值；激活后才更新任务预览。
- 长按计时完成：确认仍为单指、仍在阈值内，再捕获指针并激活对应动作。
- `pointerup`：`pending` 按点击处理；`cancelled` 不处理；`active-*` 提交最终结果。
- 桌面鼠标沿用立即激活分支。

### 5.4 CSS 边界

- 默认任务卡片和抓取点不得永久使用会吞掉纵向滚动的样式。
- 只有活动拖动状态才应用禁止选择、拖动光标和高亮效果。
- 日历滚动容器继续保留纵向惯性滚动和 overscroll 控制。

## 6. 测试与验收

### 6.1 自动测试

- 触控按下后 449ms 不激活，450ms 后激活。
- 长按前位移超过 10px 后永久取消本轮激活。
- 小于等于阈值的手指抖动不取消候选。
- 普通滑动不调用日程更新函数。
- 长按主体后拖动只更新位置，不改变时长。
- 长按顶部/底部抓取点后只更新对应时间边界。
- `pointercancel`、丢失捕获和卸载都清理计时器及自动滚动。
- 鼠标仍可立即拖动。

### 6.2 真机验收

在 Android Edge/Chrome 和 iPhone Safari 至少验证：

1. 从任务卡片中央向上或向下滑动，页面顺畅滚动且任务不移动；
2. 从顶部或底部抓取点开始滑动页面，任务时长不变化；
3. 长按主体出现反馈后拖动，任务位置正确改变；
4. 长按抓取点出现反馈后拖动，任务时长正确改变；
5. 长按后不移动直接松手，不产生数据变化；
6. 拖动到可视区边缘时自动滚动仍工作；
7. 轻点任务仍能打开详情；
8. 快速连续操作不会留下卡死、高亮或幽灵预览。
